# ga-tiles

Тайлы ветра, температуры и авиационных опасностей для карты приложения Aviation Weather. Источник — прогноз NOAA GFS (сетка 0.25°). Конвейер на Python скачивает GRIB2, режет глобальное поле на PNG-тайлы и выкладывает их на Firebase Hosting (`https://ga-tiles.aviationweather.pro/wind/v1/`).

## Источник

- Данные: `pgrb2.0p25` из открытого бакета NOAA на AWS, `https://noaa-gfs-bdp-pds.s3.amazonaws.com/gfs.YYYYMMDD/HH/atmos/gfs.tHHz.pgrb2.0p25.fNNN`. Рядом лежит `.idx`.
- Скачивание: только нужные поля, HTTP Range по байтам из `.idx`, около 66 MB на шаг, из них 26 MB — поля только `sky/v1` (замер 10.11.2026, прогон 12Z: 93 поля; без `sky/v1` — 51 поле, 40 MB; `--sky-only` — 52 поля, 34 MB). Повторов нет: сбой валит запуск, следующий час пробует снова.
- Прогон: самый свежий из 00, 06, 12, 18Z за последние 24 ч, у которого уже есть `f066.idx`.
- Шаги: 3…66 ч через 3 ч, 22 кадра. Если в `.idx` шага нет хотя бы одного нужного поля, запуск падает с `ValueError` и номером шага.
- Поля:

| Назначение | Поля GFS | Имя в `read_fields` |
|---|---|---|
| Ветер и температура на уровнях | `UGRD VGRD TMP` на 900, 850, 800, 750, 700, 600, 500, 400, 300 mb | `u v t` |
| Обледенение | `RH` на 900…600 mb | `r` |
| Турбулентность | `HGT UGRD VGRD` на 600, 500, 400, 300, 250 mb | `gh u v` |
| У земли | `UGRD VGRD` 10 m, `TMP` 2 m, `PRES:surface` | `10u 10v 2t sp` |
| Изотерма 0° | `HGT:0C isotherm`, м над уровнем моря; 0 там, где у GFS нет изотермы | `zero` |
| Грозы | `CAPE:180-0 mb above ground`, мгновенный `CPRAT:surface` | `cape cprat` |
| Условия полёта | `HGT:cloud ceiling`, `HGT:surface`, `VIS:surface`, `GUST:surface` | `ceiling orog vis gust` |
| Облачность (`sky/v1`) | мгновенные `TCDC:entire atmosphere`, `LCDC:low cloud layer`, `MCDC:middle cloud layer`, `HCDC:high cloud layer` | `tcc lcc mcc hcc` |
| Термики (`sky/v1`) | `HPBL:surface`, м над землёй | `hpbl` |
| Верхняя граница облаков (`sky/v1`) | `TCDC HGT` на 1000, 975, 950, 925, 900, 850…100 mb через 50 | `tcc gh` на уровне |

- Поля `sky/v1` необязательны: если в `.idx` шага нет такого поля, запуск идёт дальше, а тайлы `sky/v1`, которые его читают, этого кадра не пишутся. `HPBL` у eccodes без имени (`unknown`, NCEP 0.3.196), в `read_fields` он `hpbl`.

## Тайл

- Узлы тайла (zoom z, ряд r, колонка c): шаг s = 1° / 0.5° / 0.25° для z = 1 / 2 / 3, сторона 180·s. Юг = −90 + r·180·s, запад = −180 + c·180·s. Ряд считается от 90°S, колонка от 180°W.
- Узлы — каждый `stride` = 4 / 2 / 1 узел глобальной сетки 0.25° (1440 × 721). Восточный край последней колонки (180°) — это колонка −180°. Верхний край верхнего ряда — 90°N.
- Тайлов на уровень и кадр: 2 (z = 1), 8 (z = 2), 32 (z = 3).
- Уровни: `sfc` (10 м, 2 м), 900, 850, 800, 750, 700, 600, 500, 400, 300 hPa.
- PNG RGB 8 бит, 181 × 182, без альфы и без цветовых чанков (sRGB, gAMA, iCCP).
  - Строка 0: пиксели 0…7 несут 24 байта = `struct.pack("<6f", uMin, uMax, vMin, vMax, tMin, tMax)` по R, G, B подряд. Остальное — нули.
  - Строки 1…181: узлы с севера на юг, в строке с запада на восток. R = u (kt), G = v (kt), B = T (°C).
  - Байт 0 во всех трёх каналах — нет данных (любое из u, v, T = NaN). Данные: `b = 1 + round((x − min) / (max − min) · 254)`; при max = min `b = 1`. Обратно: `x = min + (b − 1) · (max − min) / 254`. Ошибка ≤ (max − min) / 508: для струи −80…+220 kt — 0.6 kt.
- Путь: `wind/v1/{run:yyyyMMddHH}/{frame:yyyyMMddHH}/{sfc|900|…|300}/{z}/{r}/{c}.png`.

## Тайлы опасностей

Формат и сетка — как у тайла ветра (заголовок min/max, байт 0 — нет данных), тот же прогон, кадры и манифест.

- Путь: `hazards/v1/{run:yyyyMMddHH}/{frame:yyyyMMddHH}/{sfc|900|850|…|300|col}/{z}/{r}/{c}.png`.
- `sfc`: R = нижняя граница облаков над землёй, ft, 0…12 000; 12 000 значит: нет или выше. G = видимость, SM, 0…10. B = порыв у земли, kt. На z = 1 и 2 нижняя граница и видимость берут минимум вокруг узла (окно ±stride / 2): клочок тумана между узлами не пропадает. Сломанное поле стоит только тайлов `sfc` этого кадра. Высота GFS над уровнем моря (сверка 05.11.2026: на любой высоте рельефа поле не ниже 9 м над ним), поэтому из неё вычитается `HGT:surface`; около 20 000 gpm значит «нет».
- Уровень hPa:
  - R = `S` турбулентности (Ellrod TI1, сдвиг ветра к соседним уровням по `gh`). Только 500, 400, 300 hPa, ниже R = 0.
  - G = `S` обледенения (T и RH, максимум 0.7). Только 900…600 hPa, выше RH не скачивается и G = 0.
  - B = изотерма 0° в сотнях футов над уровнем моря, из `HGT:0C isotherm`. Значение одно на все уровни. 0 значит: земля замёрзла (`2t` ≤ 0 °C) или у GFS нет изотермы. Там, где над холодной землёй лежит тёплый слой, тоже 0.
  - Нет данных: под землёй (`sp` < L × 100 Па), а на 500…300 hPa ещё и полярнее ±85° (турбулентность).
- `col`: R = `S` грозы (√ произведения факторов CAPE и темпа), G = CAPE, J/kg (`CAPE:180-0 mb above ground`, самая неустойчивая частица в слое 180 hPa у земли), B = мгновенный темп конвективных осадков, mm/h (`CPRAT:surface` · 3600). Все три канала расширены на ±0.5° — максимум по ±2 узлам 0.25° до нарезки, на всех зумах: карточка показывает самые сильные значения в пределах ~30 NM.
- `S` — тяжесть 0…1, одна шкала: `≥ 0.25` слабая, `≥ 0.5` умеренная, `≥ 0.75` сильная. Пороги — в `windtiles/hazards.py`.
- На z = 1 и 2 каналы `S` уровней hPa берут максимум по узлам 0.25° вокруг узла (окно ±stride / 2); `S` грозы уже расширен на ±0.5° и, как остальные каналы, берётся узлом.

## Тайлы облачности `sky/v1`

Слои «Clouds, aviation» с выбором модели. Отдельное семейство: тайлы `wind/v1` и `hazards/v1` от него не меняются ни в одном байте (`test_wind_and_hazard_tiles_are_unchanged_by_the_sky_family`). Моделей двенадцать: GFS из GRIB NOAA (тот же прогон и кадры, что у `wind/v1`) и одиннадцать из открытого бакета Open-Meteo, см. «Модели бакета Open-Meteo».

- Пути:
  - `sky/v1/models.json` — модели из реестра `windtiles/models.py`: `[{"id": "gfs", "title": "GFS", "km": 25, "bbox": [-90, -180, 90, 180], "zoom": 3, "layers": ["clouds", …, "thermals"]}]`. `bbox` — юг, запад, север, восток данных модели; `layers` — `MapLayer.rawValue` приложения. В списке только модели, чей `sky/v1/{model}/manifest.json` лежит в сайте (`models.models_json`): сборка GFS в CI пишет GFS одну, локальный сайт со всеми моделями — все десять. Файл и манифесты пишутся через временный файл и переименование.
  - `sky/v1/{model}/manifest.json` — как `wind/v1/manifest.json`.
  - `sky/v1/{model}/{run:yyyyMMddHH}/{frame:yyyyMMddHH}/{base|cloud|sky}/{z}/{r}/{c}.png`.

| Папка | R | G | B |
|---|---|---|---|
| `base` | нижняя граница облаков над землёй, ft, 0…12 000; 12 000 значит: нет или выше | видимость, SM, 0…10 | CAPE, J/kg, без расширения на ±0.5° |
| `cloud` | нижний ярус, % | средний ярус, % | верхний ярус, % |
| `sky` | общая облачность, % | высота пограничного слоя (верх термиков) над землёй, ft | верхняя граница облаков над уровнем моря, ft |

- Верхняя граница — `HGT` самого высокого уровня 1000…100 mb над землёй (`sp` ≥ L × 100 Па), где `TCDC` уровня ≥ 50 %. Нет такого уровня — нет данных.
- PNG и заголовок — как у тайла ветра. Нет данных — по каналу: байт 0 только в том канале, где значения нет (у `wind/v1` и `hazards/v1` байт 0 во всех трёх).
- Сетка любой модели: шаг узлов s = 2^(1 − z)°, z = 1…7, сторона тайла 180·s, 181 × 181 узел; z = 1…3 совпадают с `wind/v1`. Поле модели нарезает `windtiles/tiles.write_tiles`: регулярная сетка широта-долгота с шагом s её максимального зума, глобальная (360°, замыкается по долготе) или область (вне неё нет данных). Пишутся зумы 1…z, тайл — только если область заходит внутрь него и в нём есть данные.
- Грубые зумы — узел своей сетки по окну ±stride / 2 узлов максимального зума, по каналу: ярусы и общая облачность — среднее, нижняя граница и видимость — минимум, CAPE и верхняя граница — максимум, термики — узел.
- Сломанное или отсутствующее поле стоит только своей папки в этом кадре.

### Модели бакета Open-Meteo

`windtiles/om_source.py` читает `https://openmeteo.s3.amazonaws.com/data_spatial/{bucket}/{run:yyyy/MM/dd/HHmm}Z/{valid:yyyy-MM-ddTHHmm}.om` (CC BY 4.0, без ключа): один файл на кадр со всеми полями модели, качаются только байты нужных полей (HTTP Range). Поле пересчитывается билинейно на сетку максимального зума модели, сетки — широта-долгота, проекции (Ламберт, равновеликая азимутальная), повёрнутая широта-долгота (HRDPS) и редуцированная гауссова O1280 ECMWF.

- Поля: `cloud_cover` (R `sky`), `cloud_cover_low/mid/high` (`cloud`), `cloud_base` (R `base`, только UKV), `visibility` (G `base`), `cape` (B `base`), `boundary_layer_height` (G `sky`, ECMWF и HRRR) — какие читать, решают `layers` модели (`build_models.VARIABLES`). Единицы сверяются с файлом (`%`, `m`, `J/kg`), чужие роняют кадр. Верхней границы облаков нет ни у одной модели бакета: B `sky` пуст. Канала, которого у модели нет, нет во всём тайле (байт 0); папка, у которой нет всех трёх, не пишется (`sky` у AROME-HD).
- `bbox` — настоящая область данных. У проекций и повёрнутой сетки (ALADIN, UKV, HRRR, HRDPS) это широта и долгота краёв сетки, а не две точки из BBOX в WKT бакета (это углы сетки); всё округлено наружу до 0.01° (замер 10.11.2026). Глобальное поле приходит с колонкой 180°E, равной колонке 0; она отбрасывается, и `write_tiles` замыкает поле по долготе.
- Прогон: самый свежий завершённый из часов `Model.runs`: 00, 06, 12, 18Z (`latest.json` часто указывает на короткий промежуточный прогон); у MSM только 00 и 12Z — его прогоны идут каждые 3 ч, но дальше +39 ч доходят только эти два, до +78 ч. Кадр берётся, только если он есть в прогоне: прогон короче 48 ч заканчивается раньше.
- UKV `cloud_base`: м над землёй, 0 значит то «облаков нет», то облако у земли. На сетке модели, до пересчёта (`build_models.clean_source`): 0 при `cloud_cover_low` клетки ≥ 50 % — база 0 ft (туман), меньше 50 % — «нет», +inf. В кадре +6 / +15 ч прогона 10.11.2026 12Z нулей 13 / 16 % клеток, из них базой 0 ft становятся 12.5 / 21 %, у трети-половины этих клеток видимость меньше 1 000 m. +inf не смешивается с настоящими базами (`om_source.regrid`): узел берёт взвешенное среднее конечных углов, +inf — только если все четыре угла +inf; потом +inf → 12 000 ft до минимума по окну грубых зумов. Иначе на краю облака билинейка выдумывала бы базу 150 m из «нет» как 0 и 300 m: так было у 89 % узлов края, теперь ни у одного.
- HRDPS `cape`: в 7–9 клетках кадра −1000 — нет данных; отрицательный CAPE любой модели становится NaN до пересчёта.
- ALADIN `visibility` обрезана в бакете на 7 480 m: от 7 400 m пишется 10 SM, иначе вся ясная погода выглядела бы как MVFR.
- Сборка: кадры идут в 8 потоков (`--workers`), поток держит в памяти один кадр. Сбойный кадр не входит в манифест, его тайлы (если есть) остаются без ссылок: удалить их значило бы сломать уже выложенный манифест того же прогона. Манифест пишется последним и только из записанных кадров; нет ни одного кадра — модель падает, её старый манифест остаётся. Упавшая модель не мешает остальным, `models.json` пишется в конце из того, что лежит в сайте; код выхода 1.

## Сверка

`tools/calibrate.py` (вне пакета и CI) сверяет пороги последнего прогона GFS (шаги 3, 6, 9, 12) с PIREP/AIREP и конвективными SIGMET AWC — теми же запросами, что у приложения:

```bash
.venv/bin/python -I tools/calibrate.py --work "$TMPDIR/wx-calib"
```

- Турбулентность: отчёты MOD+ на FL200+; попадание — `S ≥ 0.25` в ±0.5° и ±1 уровень от ближайшего из 500, 400, 300 hPa в ближайшем кадре. Площадь — доля глобуса (вес `cos φ`) с `S ≥ 0.5` на 500 / 400 / 300 hPa, среднее по кадрам. Цель: ≥ 50 % попаданий при площади ≤ 10 %.
- Грозы: SIGMET TS / CONV / CB часа запроса; доля площади полигонов под `S ≥ 0.25` колонки (уже расширенного на ±0.5°) в ближайшем кадре. Цель: ≥ 60 %, порог для подбора опор — 40 %.


## Атрибуция

Основано на данных NOAA GFS 0.25° (public domain). NOAA не поддерживает и не одобряет этот сервис.

Изменения относительно исходных данных:

- сетка 0.5° и 1° прорежена из 0.25°;
- 8 бит на значение (линейное квантование между min и max тайла);
- маска под землёй по `sp`: узел уровня L hPa без данных, если `sp` < L × 100 Па (SFC не маскируется);
- единицы: u, v переведены из м/с в узлы, T — из K в °C;
- производные величины: индекс турбулентности (Ellrod TI1), потенциал обледенения по T и RH, изотерма 0° в сотнях футов, индекс грозы по CAPE и темпу конвективных осадков, его зоны, CAPE и темп расширены на 0.5°; на 0.5° и 1° индексы турбулентности и обледенения — максимум вокруг узла;
- `sky/v1`: высота пограничного слоя в футах, верхняя граница облаков в футах по профилю облачности; на 0.5° и 1° облачность — среднее вокруг узла.

Модели `sky/v1`, кроме GFS, — из открытого бакета Open-Meteo (CC BY 4.0): ECMWF IFS (CC BY 4.0), DWD ICON, ICON-EU, ICON-D2, CHMI ALADIN, Météo-France AROME и AROME-HD, Met Office UKV, NOAA HRRR, ECCC HRDPS, JMA MSM. Изменения: билинейный пересчёт на сетку широта-долгота (база UKV — без смешивания с «облаков нет»), 8 бит на значение, единицы — футы и мили, видимость ALADIN от 7 400 m — 10 SM, на грубых зумах — среднее, минимум или максимум вокруг узла.
